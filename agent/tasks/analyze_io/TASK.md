# Analyze I/O

## ID

analyze_io

## Description

Анализ ввода-вывода: определение используемых I/O портов, классификация обращений IN/OUT, сравнение с известными портами Vector-06C, поиск аномалий.

## Procedure

1. **Сбор I/O trace**
   - Получить трассировку I/O через `debug_get_io_trace`.
   - Если трассировка пуста — запустить выполнение через `debug_run`, затем паузу и повторный сбор.
   - Определить все порты, к которым были обращения.

2. **Классификация портов**
   Для каждого порта из трассировки определить:
   - **Известный порт**: есть в документации (io.md) с определённой функцией.
   - **Зарезервированный порт**: порт в известном диапазоне, но функция не подтверждена.
   - **Неизвестный порт**: порт вне известных диапазонов (0x11–0x13, 0x16–0x17, 0x1D–0xFF).

3. **Анализ IN операций**
   - Для каждого порта IN: определить, какое значение возвращается.
   - Сравнить с ожидаемым поведением (например, порт 0x02 — клавиатурный скан).
   - Определить, как используется возвращённое значение (маскирование, сравнение).

4. **Анализ OUT операций**
   - Для каждого порта OUT: определить записываемые значения.
   - Определить паттерны:
     - Инициализация (однократная запись в начале).
     - Обновление (периодическая запись, например scroll, палитра).
     - Данные (последовательные записи, например AY-регистры).

5. **Анализ последовательностей**
   - Определить типичные последовательности I/O:
     - AY access: OUT 0x15 (address) → OUT 0x14 (data).
     - PIA1 init: OUT 0x00 (control word) → OUT 0x01/0x02/0x03 (ports).
     - Palette: OUT 0x0C (data) → commit on next scanline.
   - Проверить корректность последовательностей.

6. **Статический анализ I/O инструкций**
   - Дизассемблировать код через `debug_disassemble`.
   - Найти все IN/OUT инструкции.
   - Для каждой: определить порт, направление, контекст.
   - Использовать `debug_get_xrefs` для определения частоты использования.

7. **Поиск аномалий**
   - Обращение к порту без предварительной инициализации.
   - Запись неизвестных значений.
   - Обращение к зарезервированным/неиспользуемым портам.
   - Неправильная последовательность AY access.

## Checks

- Все ли используемые порты имеют известное назначение?
- Корректны ли последовательности доступа к AY?
- Нет ли обращений к зарезервированным портам?
- Соответствуют ли I/O паттерны известным устройствам?
- Нет ли гонок (OUT без ожидания commit)?

## Limitations

- Трассировка покрывает только выполненные пути.
- Условные I/O (внутри ветвлений) могут не проявиться.
- Некоторые порты имеют разное поведение при IN и OUT.
- Без документации на конкретный ROM невозможно определить намерение программиста.
