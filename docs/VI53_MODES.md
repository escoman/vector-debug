# VI53 (i8253) — режимы счётчиков и их трактовка в Sound window

Сводка по управляющему слову таймера VI53 (i8253 в Vector-06C):
формат CW, чем шесть аппаратных режимов отличаются друг от друга, почему
значений восемь, и как дебаггер решает, «играет» ли канал.

## Порты

| Порт | Назначение |
|------|-----------|
| `0x08` | Управляющее слово (CW) счётчика |
| `0x0B` | Counter 0 — данные делителя (в Sound window = «i8253 Channel 1») |
| `0x0A` | Counter 1 — данные делителя («i8253 Channel 2») |
| `0x09` | Counter 2 — данные делителя («i8253 Channel 3») |
| `0x14` / `0x15` | AY-3-8912 (регистр / данные) |

Номер счётчика из порта: `ctr = (~port) & 3`.

## Формат управляющего слова

```
bit:   7 6 | 5 4 | 3 2 1 | 0
       ───   ───   ─────   ─
SC     счётчик: 00=Counter0 (порт 0x0B), 01=Counter1 (0x0A),
                10=Counter2 (0x09), 11 — не существует
RL     что делаем: 00 = read-back latch (только прочитать, не трогать),
                    01 = только LSB, 10 = только MSB, 11 = LSB+MSB
M2 M1 M0 = режим   (3 бита)
BCD      0 = двоичный делитель, 1 = BCD (делитель до 10000)
```

Примеры из реальных ROM:

| Значение CW | Разбор |
|-------------|--------|
| `0x30` | Counter0, LSB+MSB, режим 0 (Arkanoid — инициализация) |
| `0x10` | Counter0, только LSB, режим 0 (Arkanoid — мелодия) |
| `0x36` / `0x76` / `0xB6` | Counter0/1/2, LSB+MSB, режим 3 (putup.rom) |

## Почему режимов 8 (0–7)

На режим выделено **3 бита** → 2³ = 8 значений. Полноценных режимов
аппаратно **шесть**: «семёрка» — алиас тройки. В даташите Intel слово «Mode»
в битах 3–1 кодируется как `011`/`111` для wave generator, то есть режим 7
буквально = «LSB/MSB + режим 3», старший бит маскируется. Эмулятор делает
ровно это (`vendor/v06c-emu/src/8253.h`, `SetMode`: `(new_mode & 0x03)`), и
адаптер дебаггера тоже (`src/debug_adapter.cpp`: `(timerModes_[ctr] & 3) == 3`).

## Шесть режимов

Ключевое различие — **что делает выход OUT между «загрузить делитель» и
«счётчик досчитал до нуля»**.

| Режим | Имя | Поведение OUT | Для звука |
|-------|-----|---------------|-----------|
| 0 | Interrupt on terminal count | Идёт LOW, при досчитывании **щелкает в HIGH и сидит** до следующей загрузки | Один фронт на загрузку. Сам по себе «тихий», но при частой перезагрузке = PWM-тон |
| 1 | Hardware-trigged one-shot | Как 0, но стартует по фронту на входе GATE | То же, триггер от внешних событий |
| 2 | Rate generator | **Автоколебания**: в конце каждого периода одна «иголка» на 1 такт, счётчик перезагружается сам | Частота = f/делитель. Непрерывный тон, но не меандр (коэффициент заполнения 1/16) |
| 3 | Square wave generator | **Автоколебания**: меандр, перезагружается сам, HIGH на N/2 и LOW на N/2 | Основной «музыкальный» режим — нота живёт без участия CPU |
| 4 | Software trigged strobe | HIGH всё время, по досчитывании **одинокий LOW** на 1 такт, потом снова HIGH | Не звук, одиночный импульс |
| 5 | Hardware trigged strobe | То же, но по GATE | Не звук |
| 6 | — | не реализован, ведёт себя как 0 или как 2 (зависит от stepper'ов) | — |
| 7 | — | алиас режима 3 | см. 3 |

Принципиальная разница:

- **Режимы 2/3 автономны** — CPU один раз загрузил делитель, и дальше
  осциллятор гудит сам. Поэтому `sounding` в режиме 3 горит от момента
  загрузки до следующего CW.
- **Режимы 0/1/4/5 — одноразовые**: после досчёта выход залипает в одном
  уровне и молчит, пока CPU не перезагрузит делитель.

## PWM-мелодия: режим 0 как источник звука

«Хитрый» способ играть мелодию, которым сделаны аркадные темы на Векторе:
ROM в **режиме 0** на **каждом кадре** пишет новый делитель в порт счётчика
(например `OUT 0x0B`). Каждый завершившийся «загруз» счётчика даёт один фронт
на выходе → средняя частота следования фронтов = высота ноты. Для слуха это тот
же тон, но на шине это выглядит как частые записи в таймер, а не как
работающий осциллятор.

Признаки на шине портов (Arkanoid, `Arkan_Sample2_NoBuzz2.rom`):

- Инициализация по адресу `0x013C`: `MVI A,30 / OUT 08` (Counter0, LSB+MSB,
  режим 0), загрузка `0x01/0x00`, затем `MVI A,10 / OUT 08` (Counter0, только
  LSB, режим 0).
- Цикл мелодии `0x01B8–0x01D2`: `OUT 0x0B` с нарастающими значениями делителя.
- Не задействованы ни AY (порты `0x14/0x15`), ни ленточная пищалка (PIA PC0)
  — отсюда «NoBuzz» в имени.

## Реализация

### Эмулятор ядра

`vendor/v06c-emu/src/8253.h` — `CounterUnit::SetMode` разбирает `mode_int`
по `switch` для 0–5 (с фолдингом 2/3 через `&3` и 7→3); режимов 6/7 как
отдельных нет.

### Адаптер дебаггера (измерение)

`src/debug_adapter.cpp`, хук `io.onwrite`:

- Порт `0x08`: `ctr = (value>>6)&3`, `latch = (value>>4)&3`,
  `mode = (value>>1)&7`. При `latch != 0` вызывается `SetMode()` — он
  **выключает** счётчик (`timerSounding_[ctr] = false`); это единственный
  способ остановить ноту. `latch == 0` — read-back, ничего не меняет.
- Порты `0x09–0x0B`: байты копятся согласно `latch`-режиму (LSB+MSB / LSB / MSB).
  По завершении загрузки:
  - `timerLoadCount_[ctr]++` — счётчик **завершённых загрузок делителя** за
    интервал между снапшотами;
  - `timerSounding_[ctr] = ((timerModes_[ctr] & 3) == 3) && loadValue != 0`
    — только режим 3 с ненулевым делителем даёт «сам себе тон» (sustained).
- В `soundSnapshot()` счётчик конвертируется в
  `TimerChannelState::loadsSinceLast` и `TimerChannelState::loadRateHz`
  (по стенным часам `std::chrono::steady_clock`, значит порог не зависит от
  FPS GUI), после чего обнуляется.

### Sound window (решение об активности)

`gui/sound_window.cpp`, `analyzeSnapshot()` — две модели для i8253:

- **Режим 3** (`sounding`) — бар горит от загрузки до отмены.
- **Режим 0/1 + ≥ `kPwmMinLoadsPerSec` (30/сек) + ненулевой делитель** —
  канал активен и флагуется `retrigger`, то есть PWM-мелодия. Порог 30 Гц —
  низ музыкального основного тона; ниже — это тайминг-трафик, а не звук.

Подсветка спецрежима (`drawSoundLog(..., bool retrigger)`):

- подпись канала получает суффикс `[PWM re-trigger]` и янтарный цвет;
- рамка графика — янтарная, толщиной 2 px;
- в сводке — янтарная строка `mode N — PWM melody (X re-loads/sec)` с
  пояснением, что офлайн-парсер MIDI декодирует **только** режим 3
  (`src/audio_midi.cpp`: `if (!v.tone) continue;`), так что такая мелодия
  в `.mid` не разберётся;
- строка режима 3 имеет пояс `[square wave, sustained]`.

### Почему режим 2 не считается тоном

Технически режим 2 — осциллятор, но узкие импульсы раз в период на практике
это таймер/прерывания/частота дискретизации, а не мелодия; в ROM'ах Вектора
он для «тика» и используется. Если его всё-таки захотим показывать, данные уже
проброшены в снапшот (`TimerChannelState::mode`) — достаточно добавить
отдельный стиль отображения (например, пунктирный бар).
